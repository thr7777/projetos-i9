Resumos das aulas do curso de Git e Github - Canal: Guanabara

Um repositório é o local onde o projeto fica armazenado junto com seu histórico de alterações. Ele contém os arquivos do projeto e as informações necessárias para acompanhar as diferentes versões que foram criadas ao longo do desenvolvimento. Um repositório pode estar armazenado no computador do desenvolvedor ou em um serviço online. O GitHub é uma plataforma online que permite guardar repositórios, compartilhar projetos e trabalhar em equipe. Ele facilita o acesso aos projetos e permite que diferentes desenvolvedores possam colaborar no mesmo trabalho. Dessa forma, o projeto pode ficar disponível na internet e ser acessado pelos membros da equipe.

O Git é uma ferramenta usada para controlar as versões de um projeto. Ele registra as alterações feitas nos arquivos ao longo do tempo, permitindo acompanhar o histórico do projeto e verificar o que foi modificado em cada versão. Dessa forma, caso algum problema aconteça, é possível voltar para uma versão anterior do projeto.

A evolução do controle de versões passou por várias ferramentas. Primeiro surgiu o CVS, que era usado para controlar as versões dos arquivos e ajudar no trabalho em equipe. Em 2000, surgiu o SVN, que trouxe melhorias em relação ao CVS. Depois, o desenvolvimento do Linux passou a usar o BitKeeper, um sistema de controle de versão distribuído. Porém, por problemas relacionados à licença, o BitKeeper deixou de ser usado. Em 2005, Linus Torvalds criou o Git, um sistema de controle de versão distribuído, rápido e eficiente. Em 2008, surgiu o GitHub, uma plataforma que permite armazenar projetos que usam Git e facilita o trabalho entre desenvolvedores. Com ele, é possível compartilhar códigos, acompanhar tarefas, registrar problemas e revisar alterações. Em 2018, o GitHub sofreu um grande ataque DDoS, que chegou a aproximadamente 1,35 bilhoes e durou cerca de 20 minutos. Mesmo assim, a plataforma conseguiu continuar funcionando usando sistemas de proteção contra ataques.

para instalar o git, basta baixar o programa para o sistema que será usado e seguir os passos de instalação. Para verificar se ele realmente foi instalado, basta usar o comando git --version no terminal

Para se criar um repositorio, bastar criar uma pasta onde seus arquivos estarão, após isso, entramos na pasta a qual está o nosso projeto e iniciamos o repositorio com (git init). após isso, basta adicionar os arquivos com git add, e para salvar alterações usamos (git commit -m "mensagem"). Se quisermos adicionar no git hub, basta criar um repositório no site e adicionar a pasta que contem os arquivos

No vídeo, Guanabara mostra como instalar o GitHub Desktop no Linux. Primeiro, ele acessa o perfil do usuário shiftkey no GitHub e entra no repositório da versão 2.4.0 para Linux PC. Depois, ele baixa o arquivo .deb, que é um pacote de instalação usado em sistemas baseados em Debian. Por fim, ele executa o arquivo .deb usando a própria ferramenta de instalação do Linux, realizando a instalação do GitHub Desktop no computador.

Para clonar um repositorio, basta primeiro entrarmos no git hub, e copiar o link do repositório a qual queremos clonar no nosso sistema, após estar com o link do repositório, basta abrir o terminal e digitar o comando (git clone ) e o link do repositório copiado. Após isso, o repositório será clonado no dispositivo, para enviar as modificações, é preciso fazer o login no git hub pelo terminal e conectar o repositorio local com o repositorio do site. Para enviar os arquivos modificados, basta fazer um git push

O vídeo mostra como colocar projetos antigos no GitHub para facilitar o acesso e evitar que eles sejam perdidos. Para isso, ele cria um repositório pelo GitHub Desktop e conecta uma pasta do computador a ele. Depois, coloca os arquivos do projeto na pasta e faz um commit pelo GitHub Desktop para salvar as alterações no repositório.

No GitHub, Issues são utilizadas para registrar e acompanhar problemas, tarefas, ideias e melhorias relacionadas a um projeto. Elas podem ser usadas, por exemplo, para informar um bug, sugerir uma nova funcionalidade ou registrar uma tarefa que precisa ser realizada. Depois que o problema é resolvido ou a tarefa é concluída, a Issue pode ser fechada. Já o Pull Request é utilizado quando alguém faz alterações no código e deseja que elas sejam revisadas e incorporadas ao projeto. Dessa forma, as Issues ajudam a organizar o que precisa ser feito, enquanto os Pull Requests servem para propor e revisar alterações no código.
